# Full Screening Agent Usage

`full_screening_agent.py` is the end-to-end controller for the C3F8/C3F6
extractive-distillation screening workflow.

It connects:

- molecular evidence from `../screening_api_snapshot.json`;
- Aspen-ready solvent IDs from `solvents.xlsx`;
- the zero-built Aspen BKP generated by `zero_build_aspen_agent.py`;
- prior Aspen/NSGA-II workbooks in `outputs/optimization`;
- final decision ranking, validation queues, and repair queues.

Default audit mode does not launch Aspen:

```powershell
& 'C:\Users\熊\AppData\Local\Python\bin\python.exe' .\full_screening_agent.py
```

Validate the optimization handoff without launching Aspen:

```powershell
& 'C:\Users\熊\AppData\Local\Python\bin\python.exe' .\full_screening_agent.py --run-optimization --optimization-dry-run
```

Regenerate the zero-built BKP and run its smoke validation:

```powershell
& 'C:\Users\熊\AppData\Local\Python\bin\python.exe' .\full_screening_agent.py --build-zero-bkp --zero-smoke
```

Run the selected flow-validation cases through Aspen:

```powershell
& 'C:\Users\熊\AppData\Local\Python\bin\python.exe' .\full_screening_agent.py --run-aspen-validation
```

Main outputs:

- `generated/full_agent/full_agent_decision_report.xlsx`
- `generated/full_agent/full_agent_decision_report.json`
- `generated/full_agent/full_agent_decision_report.md`
- `generated/full_agent/optimization/*_agent_nsga2.xlsx` when optimization dry-run or real optimization is requested

Wording guardrail for manuscripts:

- The zero-built BKP smoke test proves automated Aspen model generation and cold-start validation.
- The optimized process results should still be reported from the NSGA-II optimization workbooks.
- Do not describe the zero-built smoke point as the process optimum.
